协议默认将上传类请求与控制类请求分开处理：图片数据建议使用 multipart/form-data，控制命令与状态查询使用 JSON 或 HTTP GET。

基础约定

1. 通用约定

  • fileName 只传基础名，不带后缀
  • bin 文件字段表示主图数据，对应 ${fileName}.bin
  • image 文件字段表示缩略图数据，对应 ${fileName}.jpg
  • save 表示是否保存
  • show 表示是否立即显示
  • 上传请求建议使用 multipart/form-data
  • 文本字段放表单项，文件内容放文件字段
总览

2. 协议总表

2.1 接口总览

func 用途 请求格式 关键字段
upload 通用上传一组图片 HTTP POST + multipart/form-data fileName bin bin_size image image_size save show
cast 普通投图 HTTP POST + multipart/form-data fileName bin bin_size image image_size save show
update 替换旧图片 HTTP POST + multipart/form-data oldfileNames newfileNames bin bin_size image image_size save show
get_saved_images 获取已存图片列表 HTTP POST + JSON 无
ping 检查设备网络是否连通 HTTP GET 无
start_slideshow 启动轮播 HTTP POST + JSON fileNames interval
set_slideshow 设置轮播开关与周期 HTTP POST + JSON sw interval
set_wifi_work_time 设置 WiFi 工作时长 HTTP POST + JSON seconds
delete 删除选中图片 HTTP POST + JSON fileNames

2.2 通用字段

字段 类型 说明
fileName string 图片基础名，不带后缀
oldfileNames string 被替换的旧图片基础名
newfileNames string 替换后的新图片基础名
fileNames string[] 多张图片基础名列表
save boolean 是否保存到设备
show boolean 是否立即显示
sw number 轮播开关，1 表示开启，0 表示关闭
interval number 轮播切换间隔，建议单位为秒
seconds number WiFi 工作时长，单位为秒
bin_size number 主图文件大小，单位字节
image_size number 缩略图文件大小，单位字节
thumbnailUrl string 缩略图下载地址

2.3 文件字段

字段 文件名规则 说明
bin ${fileName}.bin 主图文件
image ${fileName}.jpg 缩略图文件
上传

3. upload

用途：通用上传一组图片。

表单字段：

  • func=upload
  • fileName=26422
  • bin_size=123456
  • image_size=23456
  • save=true
  • show=true
  • 文件字段 bin -> 26422.bin
  • 文件字段 image -> 26422.jpg

设备端要求：

  1. 校验 func、fileName、bin_size、image_size
  2. 校验文件字段 bin、image
  3. 校验文件大小是否分别等于 bin_size、image_size
  4. 按同一个 fileName 建立主图与缩略图关联
  5. 按 save、show 处理
  6. 返回成功或失败
投图

4. cast

用途：普通投图流程。

特点：

  • 和 upload 一样一次上传完整主图与缩略图
  • 成功后设备要记录最后一次成功 cast 的图片
  • 设备重启、OTA 后应优先显示最后一次成功 cast 的图片

表单字段：

  • func=cast
  • fileName=26422
  • bin_size=123456
  • image_size=23456
  • save=true
  • show=true
  • 文件字段 bin -> 26422.bin
  • 文件字段 image -> 26422.jpg

设备端要求：

  1. 校验 func、fileName、bin_size、image_size
  2. 校验文件字段 bin、image
  3. 校验文件大小是否分别等于 bin_size、image_size
  4. 按同一个 fileName 建立主图与缩略图关联
  5. 按 save、show 处理
  6. 记录该图片为最后一次成功 cast 的图片
  7. 返回成功或失败

成功响应建议

{
  "func": "cast_result",
  "result": 0
}

失败响应建议

{
  "func": "cast_result",
  "result": 1,
  "message": "cast failed"
}
读取设备资源

5. 获取已存图片

手机请求设备返回已保存图片列表和缩略图地址。

请求：

{
  "func": "get_saved_images"
}

响应：

{
  "func": "get_saved_images_result",
  "result": 0,
  "images": [
    {
      "fileName": "26422",
      "thumbnailUrl": "/thumb/26422.jpg"
    },
    {
      "fileName": "26423",
      "thumbnailUrl": "/thumb/26423.jpg"
    }
  ]
}

说明：

  • 设备返回列表和 thumbnailUrl
  • 手机再主动发起 HTTP GET 请求获取缩略图

失败响应建议：

{
  "func": "get_saved_images_result",
  "result": 1,
  "message": "read saved images failed"
}
轮播

6. 轮播

手机选择部分图片后，下发轮播列表。

{
  "func": "start_slideshow",
  "fileNames": ["26422", "26423", "26430"],
  "interval": 60
}

说明：

  • fileNames 顺序就是轮播顺序
  • interval 单位建议为秒

设备端要求：

  1. 校验 fileNames 和 interval
  2. 按顺序建立轮播队列
  3. 按 interval 切换
  4. 返回成功或失败

成功响应建议

{
  "func": "start_slideshow_result",
  "result": 0
}

失败响应建议

{
  "func": "start_slideshow_result",
  "result": 1,
  "message": "file not found"
}
轮播开关

7. set_slideshow

用于单独控制轮播开启或关闭，并设置轮播周期。

请求：

{
  "func": "set_slideshow",
  "sw": 1,
  "interval": 60
}

说明：

  • sw=1 表示开启轮播
  • sw=0 表示关闭轮播
  • interval 单位为分钟

成功响应建议：

{
  "func": "set_slideshow_result",
  "result": 0
}

失败响应建议：

{
  "func": "set_slideshow_result",
  "result": 1,
  "message": "set slideshow failed"
}
Note:
set_slideshow.interval is sent in seconds.
sw=1 means on, sw=0 means off.

  "result": 0
}

失败响应建议：

{
  "func": "delete_result",

联调 / 心跳

10. 连通性检查

用途：手机向设备发送一条轻量 HTTP GET 请求，用于判断当前网络是否仍然连通。

请求（建议）：

GET /ping HTTP/1.1

说明：

  • 该请求不带请求体
  • 设备端 HTTP GET 请求由 have_request 统一处理
  • 连通性检查建议在 have_request 中识别路径 /ping 并返回结果
  • 设备在线且网络可达时，应尽快返回 JSON
  • 手机端如果在约定时间内未收到响应，应按超时处理，视为当前网络不通
  • 建议手机端超时时间为 3~5 秒，具体可由实现侧配置

成功响应建议

{
  "func": "ping_result",
  "result": 0,
  "message": "ok"
}

失败判定

协议层不要求设备主动返回失败 JSON。设备不可达、连接断开或链路异常时，手机端以请求超时作为失败判定。

替换

11. update

替换旧文件。

当前前端尚未接入该接口，协议先保留。

表单字段：

  • func=update
  • oldfileNames=12345
  • newfileNames=67890
  • bin_size=123456
  • image_size=23456
  • save=true
  • show=true
  • 文件字段 bin -> 67890.bin
  • 文件字段 image -> 67890.jpg

说明：

  • 用新图片 67890 替换旧图片 12345

设备端要求：

  1. 校验 oldfileNames、newfileNames、bin_size、image_size
  2. 校验文件字段 bin、image
  3. 校验文件大小是否分别等于 bin_size、image_size
  4. 删除或覆盖旧图片
  5. 写入新主图和新缩略图
  6. 按 save、show 处理
  7. 返回成功或失败

成功响应建议：

{
  "func": "update_result",
  "result": 0
}

失败响应建议：

{
  "func": "update_result",
  "result": 1,
  "message": "update failed"
}
显示规则

12. 恢复显示规则

设备端建议：

  1. 记录最后一次成功 cast 的 fileName
  2. 重启后优先显示最后一次成功 cast 的图片
  3. OTA 后优先显示最后一次成功 cast 的图片
  4. 若该图片不存在，再走默认显示逻辑
